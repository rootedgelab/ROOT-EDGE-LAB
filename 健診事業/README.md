# サイト健診事業 — 業務基盤の使い方

営業リスト生成〜健診納品までを「しょーたの承認だけで回す」ための仕組み。
Claudeへの作業ルールはリポジトリ直下の `CLAUDE.md` に定義済み（全セッション共通）。

## フォルダ構成

```
健診事業/
├── 正本/            ← しょーたが3ファイルを置く（商品設計書・監査正本プロンプト・営業文セット）
├── リスト/          ← 営業候補リスト（CSV）
│   ├── scripts/     ← リスト生成スクリプト（Python）
│   └── dm_drafts/   ← DM下書き（{店名}.md）
├── 案件/            ← 顧客ごとのフォルダ（_template/ をコピーして使う）
├── ルール集/        ← 修正指摘を蒸留した確定ルール
├── logs/            ← 復元ログ・実行ログ（backup/ に上書き退避）
├── 司令書/          ← 朝の司令書の出力先（{日付}.md）
└── scripts/         ← 共通スクリプト（safe_move.py / make_briefing.py）
```

## 大原則（ガードレール）

- ファイル削除は一切しない。移動・上書きは `scripts/safe_move.py` 経由で復元ログに全件記録
- DM・メール等の外部送信は自動化しない。下書きまで。送信は必ずしょーた
- データ取得は公式 Places API のみ（画面スクレイピング禁止）
- 店舗データは営業目的の社内利用限定。第三者提供・公開はしない
- 効果保証・恐怖訴求の文言は生成物に入れない
- 各フェーズ完了時にしょーたの承認を取ってから次へ

---

## 最初にやること: 正本3ファイルを置く

`正本/` に以下を置く（詳細は `正本/README_正本を置いてください.md`）:
`商品設計書.md` / `監査正本プロンプト.md` / `営業文セット.md`

これが揃うまで、DM下書き・監査・計画書の生成は始まりません。

## Google Places API キーの取得（5ステップ）

1. https://console.cloud.google.com/ にログインし、新規プロジェクトを作成（例: `site-kenshin`）
2. 左メニュー「APIとサービス → ライブラリ」で **Places API (New)** を検索して「有効にする」
3. 「APIとサービス → 認証情報」→「認証情報を作成 → APIキー」でキーを発行
4. 発行したキーの「キーを制限」で、API制限を **Places API (New) のみ** に設定して保存
5. 「お支払い」で請求先アカウントを紐付け（無料枠内でも必要）。予算アラートを $10 程度で設定しておくと安心

キーは `リスト/scripts/.env` に保存する（コミット禁止・.gitignore済み）:

```bash
cd 健診事業/リスト/scripts
cp .env.example .env
# .env を開いて GOOGLE_PLACES_API_KEY=実際のキー に書き換える
```

## 営業リストの生成（フェーズ2）

初回セットアップ（venv）:

```bash
cd 健診事業/リスト/scripts
python3 -m venv venv
source venv/bin/activate        # Windowsは venv\Scripts\activate
pip install -r requirements.txt
```

実行:

```bash
# 動作確認（APIキー不要・架空データ）
python3 generate_list.py --industry "整体・接骨院" --area "名古屋市中区" --mock

# 本番（.env にキーが必要）
python3 generate_list.py --industry "整体・接骨院" --area "名古屋市中区"

# サイトチェックだけ再実行（APIを使わない・既存CSVを上書き更新）
python3 generate_list.py --recheck "../2026-07-09_整体・接骨院_名古屋市中区.csv"
```

※ ネットワーク制限のある環境（Claude Codeのリモート環境など）では店舗サイトに
接続できず、弱点が「未チェック」・繁盛度順のCSVになる。その場合は普通のPCで
`--recheck` を実行すればAPIを使わずにサイトチェックだけ完了できる（上書き前の
CSVは logs/backup/ に自動退避・復元ログ記録）。

処理内容:

1. Places API Text Search で「{業種} {エリア}」を最大60件取得（1回の実行上限）
2. 一次フィルタ: 評価4.3以上 かつ 口コミ50件以上 かつ サイトURLあり
3. 通過店舗のトップページのみを機械チェック（間隔1秒以上・負荷をかけない）:
   HTTPS / viewport（スマホ対応）/ タイトル・ディスクリプション / コピーライト年の古さ / 応答速度実測
4. 「繁盛度スコア（評価×口コミ数）」×「サイト弱さスコア」の高い順
   ＝ **商売は強いのにWebが弱い順** に並べて `リスト/{日付}_{業種}_{エリア}.csv` に出力
5. APIリクエスト数と概算コストを毎回表示（1回の実行で最大3リクエスト・約$0.11）

## DM下書き（フェーズ3）

CSV上位の店名をClaudeに指定すると:

1. そのサイトのトップページを実際に確認し、`正本/営業文セット.md` の「B. 新規向けDM」の型で、
   実在が確認できた具体的な指摘を2点入れた下書きを作成（憶測禁止）
2. `リスト/dm_drafts/{店名}.md` に保存し、CSVのステータスを「下書き済」に更新
3. **送信はしょーたが手動で行う。** 送信したらステータスを「送信済 YYYY-MM-DD」に更新

## 朝の司令書（フェーズ4）

Claudeに **「今日なにやる？」** と言うと `司令書/{日付}.md` が出力される。
手動実行も可能:

```bash
python3 健診事業/scripts/make_briefing.py
```

内容: 今日やるべきこと（優先順・所要目安）／承認待ち・返信待ち／しょーたに確認したいこと

## ファイルの移動・上書き（復元ログ）

削除は禁止。移動・上書きは必ずこれを使う:

```bash
python3 健診事業/scripts/safe_move.py <元パス> <新パス>
```

- 上書き先に既存ファイルがあれば `logs/backup/` に退避コピーしてから移動
- すべての操作を `logs/復元ログ.csv` に「元→新」で記録

## 案件フォルダの作り方

```bash
cp -r 健診事業/案件/_template "健診事業/案件/{店名}"
```

01ヒアリング → 02一次監査 → 03計画書ドラフト →（しょーた承認）→ 04納品 の順で埋める。
納品したら案件フォルダ直下に `納品済_{日付}.md` を作る（司令書が進捗判定に使う）。
